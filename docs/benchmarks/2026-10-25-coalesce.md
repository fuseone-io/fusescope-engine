# 2026-10-25 · coalesced buffers

Same machine, disks, services and traffic shape as the
[baseline](2026-10-25-baseline.md); code at 54a4a5a (buffers in WAL order,
background coalescing of request batches, strict admission, per-tenant cap).
Raw JSON in [`2026-10-25-coalesce/`](2026-10-25-coalesce/). Compare with the
[flush-stages](2026-10-25-flush-stages.md) run, which motivated the change.

Command: `fs-bench load --endpoint 127.0.0.1:4317 --duration-secs 30 --concurrency C --metrics 127.0.0.1:9464`

Request batches are now merged in the background into chunks that keep log
order, so a flush concatenates a few large batches instead of thousands of
small ones, and live rows take the memory of a packed batch.

## Reading

**Concat is no longer the largest flush stage.** Parquet encode is, at
2.5 µs per row, then sort at 0.75 µs. The next flush work is streaming row
groups so encode overlaps the buffer filling, and a cheaper sort key.

**The coalescer runs behind at 32 senders.** It merges one chunk at a time
and takes whatever is complete, 1 299 batches per chunk at 54 µs each.
Over the run it merged 187 k of 218 k request batches; the rest were cut
raw into flushes and then kept raw for the hot window, which is why
persisted memory is 903 MiB rather than the 300 MiB that chunks of this
run would take. Fixed-size groups merged in parallel on the blocking pool
would keep up and bound the per-chunk latency.

**Errors at 32 senders are the caps doing their job.** 17 504 requests were
refused by the per-tenant cap (1 GiB, persisted rows included) and the
tenant buffer cap; with the retention holding raw batches the tenant cap
is reached within the 15 s window. Coalescing before the cut, above, and
a shorter retention both shrink that. At 8 senders nothing was refused.

**Content is now reproducible.** A flush from chunks and a flush from
replayed records concatenate the same rows in the same order; the test
`coalesced_flush_matches_replay_byte_for_byte` crashes between upload and
checkpoint and expects the retry to register the same size.
